# MoviePilot-TaskConfirmPlugins

[MoviePilot V3](https://github.com/jxxghp/MoviePilot) 自定义插件仓库（个人用）。

## 插件列表

| 插件 | 说明 |
|---|---|
| **TaskConfirmMax 任务确认中心 Max** | **一体化 Max 版：确认中心 Web 服务内嵌进插件**，容器内默认监听 `0.0.0.0:8005`，页面 `/ui/pending`；指令框**直接输入搜索词**（无需前缀）；选媒体 → 选站点资源 → 自动/指定下载器下载，三阶段闭环。专配 MoviePilot，无需外部确认中心。 |
| TaskConfirmBridge 任务确认桥接 | 桥接版：**依赖外部部署的「任务确认中心」**承载卡片，把指令框的 `mp <搜索词>` 转成 MP 媒体搜索。**v2.0.0 起与 Max 版能力对齐**（媒体库已存在检查、搜索无结果提醒、内置通知直推），仅不含内嵌 Web 确认服务。两者功能重叠，**二选一启用即可**。 |

## 安装

MoviePilot → 设定 → 插件 → 插件市场，加入本仓库地址：

```
https://github.com/huiyi977/MoviePilot-TaskConfirmPlugins
```

刷新后即可在「在线插件」里安装 **任务确认中心 Max TaskConfirmMax**。

## Max 版部署要点

1. **端口映射**：插件在 **MP 容器内** 监听 8005，需要在 MP 容器上追加端口映射：
   `8005:8005`（主机端口可自定，若与宿主机已有 8005 冲突就映射成 `8006:8005`，
   并把插件的「对外访问地址」配成 `http://<主机IP>:8006`）。
2. **通知**：v2.2.0 起内置直推，不再依赖任何外部脚本。插件配置里按渠道填：
   - Bark：服务器（默认 `https://api.day.app`）+ DeviceKey
   - 企业微信机器人：完整 Webhook URL
   - Gotify：地址 + Token
   通知渠道 `wecom` / `bark` / `gotify` / `all`（all 三渠道全发）；
   凭证只存在插件配置里，代码不含任何个人信息。
   通知正文（v2.3.1 起精简）只给「标题 + 当前阶段 + 有效期 + 入口链接」，
   **不罗列候选项明细**（明细在页面上看），避免长通知被推送渠道截断。
   **搜索为 0 的提醒（v2.3.2）**：阶段 1（媒体）或阶段 2（资源）搜索结果为 0 条、或搜索报错时，
   插件会主动推一条通知说明「无结果/失败」，并提醒登录 MP 主页排查站点/索引器；
   通知里的 MP 主页入口取自配置项「MP 主页地址」（留空则用 MP 自身的对外访问地址）。
3. **页面访问**：`http://<主机IP>:<映射端口>/ui/pending`；若配置了 `api_token`，
   页面链接需带 `?token=<api_token>`（通知里的链接会自动带上）。

## Max 版使用

打开页面，在指令框**直接输入搜索词**（无需 `mp` 前缀）：

```
蜘蛛侠
```

- **阶段 1**：候选卡片（标题/年份/类型/评分/简介），点选进入下一阶段
  - 选中的媒体会**先查媒体库**（Emby/Jellyfin/Plex…，开关默认开）：已在库 → 推送一条通知并**终止**，
    不再搜资源/下载；不在库 → 继续阶段 2
  - 媒体搜索**结果为 0 或报错**时：推一条通知告知「搜索无结果」，并提醒去 MP 主页查看（不建卡片）
- **阶段 2**：站点资源卡片（`标题｜大小｜站点｜⬆做种｜🆓免费`），点选进入下一阶段
  - 站点资源**搜到 0 条或报错**时：同样推一条通知提醒，并提醒去 MP 主页查看站点/索引器状态
- **阶段 3**：自动调用 MP 默认下载器下载（可在插件里关闭，改为推送下载器选择卡片）

卡片右上角有「撤回」按钮（两段确认）；页面右上角 ❓ 是指令帮助、📜 是历史记录。

## Bridge 版配置与行为（v2.0.0）

与 Max 版能力对齐：**媒体库已存在检查**、**搜索为 0/失败主动通知**、**内置通知直推**；
不含内嵌 Web 确认服务——卡片与作答仍在外部「任务确认中心」的 H5 页面完成。

三阶段流程与 Max 一致：`mp 搜索词` → 阶段 1 选媒体 → （媒体库已存在则通知并终止）
→ 阶段 2 选站点资源（标题｜大小｜站点｜⬆做种｜🆓免费）→ 阶段 3 自动/指定下载器下载。

| 配置项 | 默认 | 说明 |
|---|---|---|
| 中心地址 | `http://192.168.5.126:8005` | 任务确认中心服务地址 |
| 中心 token | 空 | 确认中心配置了 api_token 时填写 |
| MP 主页地址 | 空 | 搜索无结果的通知里引导去 MP 自查的入口；留空自动取 MP 对外访问地址 |
| 候选上限 | 8 | 推回确认中心的候选条数上限（阶段 1 与阶段 2 共用） |
| 任务有效期 | 3600s | 确认任务超时时间 |
| 收割窗口 | 21600s | 用户点选后插件等待收割的最长时间 |
| 让确认中心推送候选通知 | 开 | 卡片通知由确认中心推送（推荐保持开启） |
| 卡片通知改由插件内置直推 | **关** | 打开后卡片通知走插件自己的通知渠道，此时建议把上面一项关掉，避免重复推送 |
| 检查媒体库已存在 | **开** | 选中媒体后查 Emby/Jellyfin/Plex：已入库 → 通知并终止（跳过资源搜索与下载） |
| 内置通知 | 开 | 搜索无结果、媒体库已存在等提示的推送开关（总开关） |
| 通知渠道 | `wecom` | bark / wecom / gotify / all（all 三渠道全发） |
| Bark 服务器 / DeviceKey | `https://api.day.app` / 空 | Bark 推送，支持「通知图片 URL」 |
| 企业微信机器人 Webhook | 空 | 完整 URL（`https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`） |
| Gotify 地址 / Token | 空 / 空 | 如 `http://192.168.5.70:18100` |
| 极简模式 | 开 | 正文只发「时间 + 一行提示」，模板可改（`{time}{kind}{title}{url}`） |

**提示记录**：阶段 1/2 搜索为 0 条或搜索失败时，除推送通知外，还会在确认中心留一条
「已完成」的提示记录（不作为待确认卡片），方便事后回看。

**历史持久化**：插件重载配置或 MP 重启后，最近记录仍在（`save_data`/`get_data`）。

**从 1.2.1 升级**：老配置里的「兜底 webhook」会自动迁移为企业微信机器人 Webhook，
其余配置项原样保留；默认行为向后兼容（卡片通知仍由确认中心推送）。
